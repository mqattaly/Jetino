# تصمیم‌های جتینو — مرحلهٔ ۳

## DEC-001 — واحد پول
- وضعیت: قطعی
- انتخاب: ریال
- دلیل: انتخاب صریح مالک محصول.
- پیامد فنی: مبلغ‌ها در دیتابیس به‌صورت عدد صحیحِ ریال (`*_rial`) ذخیره می‌شوند؛ تبدیل ممیزشناور استفاده نمی‌شود.
- تاریخ: ۲۰۲۶-۱۱-۱۷

## DEC-002 — ارائه‌دهندهٔ OTP
- وضعیت: انتخاب محصول، اتصال نیازمند پیکربندی/اعتبارسنجی
- انتخاب: کاوه‌نگار
- پیامد فنی: اتصال verify/lookup پشت تنظیمات محیطی، با کد منقضی‌شونده و محدودیت تعداد درخواست/تلاش.
- نکته: ارسال واقعی تا زمان پیکربندی کلید API و قالب تأیید در محیط، فعال/قابل‌آزمایش نیست.
- تاریخ: ۲۰۲۶-۱۱-۱۷

## DEC-003 — بک‌اند
- وضعیت: قطعی برای شروع پیاده‌سازی
- انتخاب: NestJS + PostgreSQL در قالب Modular Monolith.
- پیامد فنی: API نسخه‌دار REST و migrationهای SQL نسخه‌بندی‌شده.
- تاریخ: ۲۰۲۶-۱۱-۱۷

## DEC-004 — روش محاسبهٔ ارسال
- وضعیت: قطعی برای مدل داده؛ مبلغ باز
- انتخاب: کرایهٔ ثابت به‌ازای هر منطقه.
- پیامد فنی: مبلغ قابل‌تنظیم در تنظیمات منطقه و snapshot ریالی در سفارش؛ تا زمان تعیین مبلغ منطقه، ثبت سفارش باید متوقف بماند.
- تاریخ: ۲۰۲۶-۱۱-۱۷

## DEC-005 — کمیسیون
- وضعیت: باز
- انتخاب: درصد نهایی هنوز مشخص نشده است.
- پیامد فنی: سفارش تا زمان تعیین کمیسیون کسب‌وکار نباید مبلغ نهایی ایجاد کند؛ نرخ اعمال‌شده باید در سفارش snapshot شود.
- تاریخ: ۲۰۲۶-۱۱-۱۷
