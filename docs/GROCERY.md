# خرید از سوپرمارکت — مرحلهٔ ۱: لیست خرید متنی

این سند مدل کاری‌ای را ثبت می‌کند که برای فاز «سوپرمارکت» انتخاب شده، ساختار داده و API آن،
و آنچه در مرحلهٔ بعد اضافه می‌شود.

## ۱) مدل کاری (تصمیم‌های نهایی)

1. **مسیر اول این فاز:** مشتری به‌جای انتخاب قلم‌به‌قلم، یک **لیست متنی** می‌نویسد
   (مثلاً «۲ کیلو سیب، یک شانه تخم‌مرغ، نان سنگک»). سبد محصولات سوپرمارکت‌ها فاز بعد است.
2. **فروشگاه:** فعلاً متنی است؛ مشتری می‌تواند نام فروشگاه را بنویسد یا خالی بگذارد تا
   پیک خودش انتخاب کند. انتخاب از فهرست سوپرمارکت‌های ثبت‌شده بعد از ثبت‌نام آن‌ها می‌آید.
3. **هزینهٔ ماموریت:** مناقصهٔ ساده. همهٔ پیک‌های همان منطقه تا **۱۵ دقیقه** پیشنهاد می‌دهند،
   مشتری یکی را انتخاب می‌کند و بقیه رد می‌شوند.
4. **خرید و فاکتور:** پیک خرید می‌کند و فاکتور را ثبت می‌کند: مبلغ، **شمارهٔ کارت فروشگاه**
   و نام صاحب حساب، عکس فاکتور (اختیاری) و اقلام ریز (اختیاری؛ اگر ثبت شود جمعش باید با مبلغ
   فاکتور برابر باشد).
5. **کرایهٔ ماموریت پیش‌پرداخت است** (ضد سفارش فیک): بعد از قبول پیشنهاد، مشتری ۱۵ دقیقه وقت
   دارد کرایه را بپردازد و **تأیید آن با پشتیبانی/مدیر** است؛ تا تأیید نشود پیک نمی‌تواند
   «شروع خرید» بزند یا فاکتور ثبت کند.
6. **پرداخت کالا:** کارت‌به‌کارت **به حساب فروشگاه**؛ مشتری بعد از تأیید فاکتور، رسید را
   بارگذاری می‌کند و پیک (پس از پرسیدن از فروشنده) رسید را تأیید می‌کند. رسید بایگانی می‌ماند
   و پشتیبانی از هر دو رسید باخبر می‌شود.
7. **مهلت پرداخت کالا:** ۱۵ دقیقه بعد از تأیید فاکتور (`grocery_payment_minutes`).
8. **یادآوری و تمدید:** اگر مهلت (کرایه یا فاکتور) بگذرد، برای مشتری یک یادآوری می‌رود
   (dedupe روی اعلان) و پیک می‌تواند تا **۲ بار × ۱۵ دقیقه** تمدید کند
   (`grocery_extend_minutes` / `grocery_max_extensions`). ماموریت خودکار لغو نمی‌شود.
9. **اعتراض به فاکتور:** مشتری می‌تواند با دلیل فاکتور را رد کند؛ لیست به `SHOPPING` برمی‌گردد،
   پیک اصلاح می‌کند و دوباره می‌فرستد.
10. **استرداد:** اگر بعد از تأیید کرایه ماموریت لغو شود، مبلغ کرایه به **کیف پول** مشتری
   اضافه می‌شود (جدول `wallet_credits`، یک ردیف به‌ازای هر ماموریت).
11. **درگاه پرداخت:** هدف نهایی، پرداخت آنلاین هر دو بخش است. تا اتصال درگاه،
    `grocery_payment_mode='CARD_TO_CARD'` است؛ با `GATEWAY` شدن، درخواست کارت‌به‌کارت رد و
    مسیر آنلاین باز می‌شود (کلید درگاه هنوز وصل نیست).
12. **مدل درآمد:** از پنل مدیریت قابل انتخاب است (کلید `grocery_revenue_mode`):
    `NONE` (بدون کارمزد)، `FEE_PERCENT` (درصدی از هزینهٔ ماموریت)، `GOODS_PERCENT`
    (درصدی از مبلغ کالا)، `FIXED` (مبلغ ثابت). مقدار در لحظهٔ تأیید رسید کالا محاسبه و در
    `platform_fee_rial` ذخیره می‌شود.
13. **کارمزد از مشتری جدا گرفته نمی‌شود**؛ از سهم پیک/فروشگاه در تسویه کسر می‌شود.

## ۲) چرخهٔ وضعیت

```
OPEN ──(قبول پیشنهاد)──► ASSIGNED ──(شروع خرید)──► SHOPPING
  │                                                  │
  ├──(لغو مشتری)──► CANCELLED                        ├──(ثبت فاکتور)──► INVOICE_SENT
  └──(پایان مهلت)─► EXPIRED                          │                        │
                                                     │             (تأیید مشتری)▼
                                                     │                 AWAITING_PAYMENT
                                                     │                        │
                                                     │        (بارگذاری رسید)▼
                                                     │                      PAID
                                                     │                        │
                                                     │        (تأیید پیک)▼
                                                     └──────────── PAYMENT_CONFIRMED ──► DELIVERED
```

- لغو از طرف مشتری فقط در `OPEN`؛ بعد از آن لغو با دلیل از طرف پیک و با ثبت در
  `audit_logs` انجام می‌شود (و مشتری اعلان می‌گیرد).
- تحویل (`DELIVERED`) فقط بعد از تأیید پرداخت مجاز است.

## ۳) جدول‌ها (`021_grocery_lists`)

| جدول | نقش |
|---|---|
| `grocery_lists` | خود لیست: متن، فروشگاه، نشانی (اسنپ‌شات)، وضعیت، مهلت‌ها، فاکتور، پرداخت |
| `grocery_bids` | پیشنهاد هر پیک برای هر لیست (`UNIQUE(list_id, driver_id)`) |
| `grocery_invoice_items` | اقلام ریز فاکتور (اختیاری) |
| `platform_settings` | کلیدهای `grocery_*` (مهلت‌ها و مدل درآمد) + ستون تازهٔ `value_text` |

## ۴) API

همهٔ مسیرها زیر `/api/v1/grocery` و پشت `JwtAuthGuard` هستند.

| متد | مسیر | چه کسی |
|---|---|---|
| `POST` | `lists` | مشتری — ثبت لیست (هدر `Idempotency-Key` اختیاری) |
| `GET` | `lists/mine` | مشتری — لیست‌های خودش + تعداد پیشنهادها |
| `GET` | `lists/:id` | مشتری/پیک همان ماموریت/کارکنان |
| `POST` | `lists/:id/bids` | پیک — ثبت یا ویرایش پیشنهاد |
| `POST` | `lists/:id/bids/:bidId/accept` | مشتری |
| `POST` | `lists/:id/invoice` | پیک ماموریت |
| `POST` | `lists/:id/invoice/approve` | مشتری |
| `POST` | `lists/:id/payment` | مشتری — رسید کارت‌به‌کارت |
| `POST` | `lists/:id/payment/confirm` | پیک ماموریت |
| `POST` | `lists/:id/status` | پیک — `SHOPPING` / `DELIVERED` / `CANCELLED` |
| `POST` | `lists/:id/cancel` | مشتری — فقط تا قبل از انتخاب پیک |
| `POST` | `lists/:id/fee-payment` | مشتری — رسید پیش‌پرداخت کرایه |
| `POST` | `lists/:id/invoice/reject` | مشتری — اعتراض به فاکتور با دلیل |
| `POST` | `lists/:id/deadline/extend` | پیک — تمدید مهلت `FEE` یا `PAYMENT` |
| `GET` | `board` | پیک — لیست‌های باز منطقه + ماموریت‌های خودش |
| `GET` | `admin/grocery/receipts` | کارکنان — صف رسید کرایه و رسید کالا |
| `POST` | `admin/grocery/lists/:id/fee/confirm` | کارکنان — تأیید کرایه |
| `GET`/`PATCH` | `admin/grocery/settings` | کارکنان — مدل درآمد، روش پرداخت، مهلت‌ها |

قواعد سرور:

- مبلغ پیشنهاد بین ۱۰٬۰۰۰ و ۵۰٬۰۰۰٬۰۰۰ ریال؛ فاکتور حداکثر ۵۰۰٬۰۰۰٬۰۰۰ ریال.
- نقش‌های کارکنان برای این بخش: `SUPER_ADMIN`، `OPERATIONS_MANAGER`، `SUPPORT`.
- پیک باید `ACTIVE` باشد و اگر `require_driver_verification` روشن است، مدارک تأییدشده داشته باشد.
- پیک فقط لیست‌های منطقهٔ خودش را می‌بیند و به پیشنهاد پیک‌های دیگر دسترسی ندارد.
- رسید/فاکتور مثل بقیهٔ تصاویر اپ (حداکثر ۳۰۰KB، JPEG/PNG/WebP) اعتبارسنجی می‌شوند.
- هر تغییر وضعیت، اعلان + ردیف `audit_logs` دارد.

## ۵) گام‌های بعدی

1. **مرحلهٔ ۲ — اپ مشتری:** صفحهٔ `/grocery` (نوشتن لیست، انتخاب نشانی، دیدن پیشنهادها،
   تأیید فاکتور، آپلود رسید، پیگیری وضعیت).
2. **مرحلهٔ ۳ — اپ پیک:** بخش «لیست‌های خرید» در پنل راننده (پیشنهاد قیمت، شروع خرید،
   ثبت فاکتور با کارت فروشگاه و اقلام، تأیید رسید).
3. **مرحلهٔ ۴ — ادمین:** انتخاب مدل درآمد، صف رسیدهای در انتظار/مغایرت، گزارش کارمزد.
4. **مرحلهٔ ۵ — سوپرمارکت‌ها:** ثبت‌نام فروشگاه، دسته/محصول با واحد و موجودی، و اتصال
   انتخاب فروشگاه به لیست متنی.
